# Roadmap

The maintainer's backlog, in order: each item is done as a plan in `docs/plans/` and one PR. Agents change it only when the person asks.

- [x] **macOS and Linux on Virtualization.framework.** `trivm create macos-27` and `ubuntu-24.04` with no clicks; start, stop, list, delete; exec, cp and ssh through SSH; shot, click, type and key through the VM's display from the host; open, a window onto the running VM. Plan: [20261124-vz.md](plans/completed/20261124-vz.md).
- [x] **Windows 11 on QEMU.** `trivm create windows-11`: the arm64 ESD from the catalog of Microsoft's Media Creation Tool made into install media and installed unattended (an autounattend with the TPM, Secure Boot and online-account checks skipped, virtio-win's drivers, Win32-OpenSSH), run by Homebrew's `qemu` with HVF and `swtpm`; shot and input over QMP, the window through QEMU's VNC; commands that need the desktop through a scheduled task, as SSH's sessions have none. Plan: [20261124-windows.md](plans/completed/20261124-windows.md).
- [x] **Throwaway clones.** `trivm run <vm> -- <cmd>`: an APFS clone of a stopped VM started, the command run, the clone deleted; `trivm clone` keeps one. For tests that need a clean system each time. Plan: [20261124-clones.md](plans/completed/20261124-clones.md).
- [x] **Older systems.** macOS 15 and 26 from their IPSWs with the Setup Assistant skipped as Lima does (`.AppleSetupDone` and a LaunchDaemon that makes the user, written to the Data volume); Ubuntu 22.04 with KDE (Kubuntu's desktop); Debian 13 and Fedora 45. Plan: [20261124-older.md](plans/completed/20261124-older.md).
- [x] **The accessibility tree.** `trivm ui <vm>`: the windows and elements of the guest's desktop with their roles, names and frames, through agent-desktop put in the guest, on macOS and Linux, so an agent clicks by name (`click --name`), not by pixel. Plan: [20261124-ui.md](plans/completed/20261124-ui.md).
- [x] **Permissions for the app under test.** macOS: `trivm os sip` turns SIP off from recoveryOS, `trivm os grant` writes the TCC grants (Accessibility, Screen Recording, Input Monitoring, the microphone) for an app by path. Plan: [20261124-permissions.md](plans/completed/20261124-permissions.md).
- [ ] **A microphone in the guest.** A sound input on each system that an agent feeds from an audio file on the host, so an app's dictation is tested without the Mac's microphone and with no prompt on the host.
- [ ] **The accessibility tree on Windows.** agent-desktop's arm64 build for Windows (UI Automation) put in the guest, so `ui` and `click --name` work there too.
- [x] **Windows' screen at any size.** virtio-gpu with virtio-win's `viogpudo` display driver instead of ramfb (800×600, 1024×768 at most): 1920×1080 as on Linux. Plan: [20261127-windows-screen.md](plans/completed/20261127-windows-screen.md).
- [ ] **Cinnamon, Linux Mint's desktop.** Mint has no arm64 build, and its bugs are its desktop's, such as Wavo's on Mint 22.3 (Cinnamon's text scaling, its keyboard layout): Cinnamon on Ubuntu 24.04, Mint 22's base, beside the other desktops.
- [x] **Retina shots and the guest's screen size.** `shot` at the display's own pixels (macOS draws 3200×1800 at 2x now, and `shot` scales it to 1600×900), and the screen's size chosen per VM, e.g. 1152×720 points at 2x (2304×1440 pixels) as Wavo's covers were shot on UTM; on macOS, Linux and Windows. Plan: [20261127-screen-size.md](plans/completed/20261127-screen-size.md).

Not planned: x86 guests (emulated), Linux Mint itself (x86 only), Windows 10, macOS 11–14, images hosted by us, an app of our own beyond the VM's window.
