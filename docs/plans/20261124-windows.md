# Windows 11 on QEMU

`trivm create windows-11`: Microsoft's arm64 ISO installed unattended into a VM run by Homebrew's `qemu` with HVF and `swtpm`, driven by the same commands as the macOS and Linux VMs (start, stop, list, delete, ip, exec, cp, ssh, shot, click, type, key, open). Done when an agent installs Windows 11 with no clicks, runs a command, copies files both ways, drives the desktop and installs and opens wavo-app v0.3.0's Windows arm64 build, all checked on this Mac with shots read.

## Decisions

- The ISO: Microsoft's arm64 download page (Windows 11 26H2, 26300.9457, English), pinned by the SHA-256 the page lists. The page's own flow refuses requests that don't come from a browser (`GetProductDownloadLinksBySku` answers `Sentinel marked this request as rejected` unless the page's device-fingerprint script ran), and trivm won't imitate that: the person downloads the ISO from the page and passes it once, `trivm create windows-11 --iso <path>`; trivm checks its SHA-256 and clones it into the cache, so the next `create` needs no `--iso`.
- QEMU is the VM's process itself, no trivm process beside it: `start` starts `swtpm` (a daemon that ends when QEMU disconnects), then QEMU in a session of its own with the VM's locked `pid` file inherited, so the lock lives as long as QEMU, and writes QEMU's pid into it. trivm talks to QEMU over QMP on `qmp.sock`: `query-status`, `screendump` (PNG for shots, PPM to measure how lit the screen is), `input-send-event` (keys as QEMU's key codes, the pointer as the tablet's absolute axes, buttons), `system_powerdown`, `quit`, `device_del`, `set_password`, `query-vnc`.
- The machine: `virt` with `-accel hvf -cpu host`; edk2's `edk2-aarch64-code.fd` from QEMU's share folder and a copy of `edk2-arm-vars.fd` per VM (`efi.bin`); the system disk raw (`disk.img`, sparse) as NVMe, whose driver Windows has inbox; `ramfb` as the display, as Windows on arm64 has no virtio-gpu driver inbox (edk2's ramfb driver offers 640×480, 800×600 and 1024×768, no property sets more); `qemu-xhci` with `usb-kbd` and `usb-tablet`; `tpm-tis-device` on `swtpm`; the ISO and the seed as USB CDs while the VM is set up, removed with `device_del` once it is; the RTC in local time, as Windows expects.
- The network: QEMU's user network, `virtio-net-pci` with the VM's MAC and a host port on 127.0.0.1 forwarded to the guest's 22, chosen free at each `start` and kept in `config` (`port`); `ip` prints `127.0.0.1:<port>`, and `ssh`, `exec` and `cp` go through it (`scp://` URLs for `cp`). Its driver, NetKVM, comes from Fedora's virtio-win ISO 0.1.302 (pinned by SHA-256; the drivers are BSD-3-Clause), extracted with `tar` into the seed.
- SSH: Win32-OpenSSH's arm64 MSI 10.4.0.0 from its GitHub release (pinned by SHA-256, BSD licence), installed from the seed with trivm's key in `administrators_authorized_keys`. sshd's shell stays cmd; `exec` runs PowerShell 5.1, Windows' own, with the command line as `-EncodedCommand` (no quoting through cmd), UTF-8 output, no progress records, and exits with the last native command's code, or 1 when a cmdlet failed. `ssh` opens PowerShell too.
- The desktop from SSH: an SSH session has none, so an app started by `exec` would run unseen. `exec` and `ssh` define `desktop <program> [args]`, which registers a scheduled task run as `user` with the interactive logon type (it runs in the logged-on desktop session), starts it and removes it.
- The install: `autounattend.xml` on the seed (`seed.iso`, made by `hdiutil makehybrid`): en-US, the disk wiped (EFI, MSR, Windows), Windows 11 Pro with Microsoft's generic key for installing it (not activated), the TPM, Secure Boot and RAM checks skipped (`LabConfig`), `BypassNRO`, the local user `user` with password `1234` in Administrators, OOBE's pages hidden, one automatic logon whose first command runs `trivm-setup.ps1` from the seed: NetKVM, OpenSSH, the key, automatic logon for good, no sleep, screen-off, lock screen or automatic updates, sshd started last. Time zone: UTC (Windows names zones its own way; no table of them in trivm).
- `create` waits for SSH with the key (the install takes tens of minutes), pressing Enter for the first half-minute (the ISO's boot asks for a key), removes the CDs, then waits for the desktop like `start`: `explorer.exe` running for `user`, then the screen lit.
- `stop`: `shutdown /s /t 0` over SSH, else `system_powerdown`, then QMP `quit`, then a kill. `open`: QEMU's VNC on 127.0.0.1 (first free display) with the password `1234`, handed to Screen Sharing by `open vnc://`.
