# Throwaway clones

A test that needs a clean system each time gets one in seconds: `trivm run <vm> -- <cmd>` makes an APFS clone of a stopped VM, starts it, runs the command and deletes the clone, however the command ends; `trivm clone <vm> <name>` makes one to keep. Done when, on this Mac, a kept clone of `macos-27` runs beside the original, and a `run` on `macos-27` and on `ubuntu-24.04` touches a file in its clone and shoots it, the file absent from the original after, the time of each `run` measured.

## Decisions

- `run`'s command runs on the host, not in the guest, with the clone's name in `TRIVM_VM`: an app test needs `cp`, `exec`, `shot`, `click` and `key` on the clone, which only the host has; a command in the guest is `trivm exec "$TRIVM_VM" -- <cmd>` in it. One argument is a shell line (`sh -c`), more are run as they are, as `exec` has it. Its exit code is `run`'s (128 + the signal when a signal ended it).
- The clone goes on success, failure and Ctrl+C. While the command runs, `run` ignores SIGINT (the terminal sends it to the command too) and deletes the clone once the command exits. For a `run` that dies before (Ctrl+C while the clone starts, a kill), a reaper, `trivm _reap` in a session of its own started before the clone is made, reads a pipe whose write end only `run` has: `run` writes the clone's name, then `done` once it has deleted the clone; at the end of the input, which comes when `run` ends however it ends, a name with no `done` after it is a clone left, which the reaper stops and deletes.
- `run`'s clone of `<vm>` is `<vm>-run-<n>`, the lowest `n` free, its MAC address the original's with the last byte XORed with `n`: the same clone gets the same address each time, so a test suite run all day doesn't use up bootpd's pool of 253 addresses, whose leases last a day.
- `clone`: a random MAC address, as `create` makes; the clone isn't started. Both refuse a VM whose setup isn't done (`setup = true`) and a running one, and hold a shared lock on the original's `pid` while copying, which its process takes exclusive, so it can't start in the middle while clones made at once don't wait for each other.
- The copy: `clonefile(2)` of each file and folder of the VM's folder but the run's own (`config`, which is written anew, `pid`, `log`, `console.log`, `ctl.sock`, sockets), so a 64 GB disk is cloned in milliseconds and its blocks are shared until written. Not on APFS, `clonefile` fails and so does the clone.
- A new machine identifier for each clone, as Apple asks of VMs running at once. macOS was checked both ways with the original and a clone running at once: with the original's identifier both guests had the same serial number and platform UUID and both worked; with a new one the clone booted to its desktop with a serial number of its own, its account, settings and SSH key as they were.
- Linux: Ubuntu's network config (cloud-init's netplan, kept once the seed is gone and cloud-init has disabled itself) matched the NIC by the MAC address the VM was made with, so a clone with another one would get no address: the seed now matches the virtio NIC by its driver, and `ubuntu-24.04` is made anew with it.

## Checks

- `make check`, `make test`; unit tests for the arguments, the slot's MAC address and the network config.
- `trivm clone macos-27 x`, both running at once, a shot of each read; a clone of a running VM and of one not set up refused.
- `trivm run <vm> -- <script>` on `macos-27` and `ubuntu-24.04`: the script touches a file in the clone and shoots it, the shot read, the file absent from the original after, the exit code passed on, the clone gone; the time of each `run`.
- Ctrl+C while the clone starts and while the command runs, and a `run` killed with SIGKILL: the clone gone each time.
