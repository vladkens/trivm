# The accessibility tree

An agent sees what is on the guest's screen as named elements, not only as pixels: `trivm ui <vm>` prints the windows of the guest's desktop and their elements, each with its role, name, value where useful and frame in a shot's pixels, read by a tool trivm puts in the guest; `trivm click <vm> --name <text>` clicks an element by its name. macOS and Linux here; Windows joins when lane B's branch meets this one. Done when, on this Mac, `trivm ui macos-27` lists Wavo's window and controls with frames that match a shot and a click by name changes something visible, and the same on `ubuntu-24.04` with the Xfce terminal, with whether Wavo's UI shows to accessibility there (shots read).

## Decisions

- The tool: agent-desktop v1.3.1 (vercel-labs/agent-desktop, Apache-2.0, Rust, no network code), the roadmap's choice for macOS, on Linux too: it reads AT-SPI itself (Ubuntu 24.04 is its measured floor) and its arm64 archives are 2.3 MB (macOS) and 3.4 MB (Linux), from its GitHub release, pinned by SHA-256 (the release's `checksums.txt` and GitHub's digests agree). Not Cua Driver (trycua/cua, MIT): its Linux arm64 archive is 28 MB, each of its releases is a pre-release (five on 2026-11-24 alone) and its Linux builds a preview. agent-desktop has an arm64 Windows build too (UI Automation), for when the lanes meet.
- Only the `agent-desktop` binary goes in the guest, not the helper beside it in the archive (the clipboard's). `ui` installs it at the first use in a VM, `/usr/local/bin/agent-desktop`, the archive from trivm's cache piped over SSH into `sudo tar`; each `ui` checks its version and replaces another one.
- macOS: tccd attributes a process started over SSH to `/usr/libexec/sshd-keygen-wrapper` (its log: `responsible_path=/usr/libexec/sshd-keygen-wrapper`), so agent-desktop's own grant doesn't count there; a grant to sshd-keygen-wrapper would give Accessibility to anything run over SSH, the app under test too when `exec` starts it, and hide its missing grant. So agent-desktop runs as a launchd job in the user's GUI domain (`launchctl bootstrap gui/<uid>`, run once, its output to files), its own responsible process, and has Accessibility by its path, granted as `grant` does at install, which needs SIP off: `ui` says so with SIP on. A run costs 0.2 s. It never runs without the grant: macOS answers an untrusted process's first AX call with its own prompt on the guest's screen ("“agent-desktop” would like to control this Mac", seen once here), so each run first reads the grant's row in TCC's database (root can't with SIP on) and grants it when it's missing.
- Linux: run over SSH as it is: sshd's `DISPLAY=:0` and pam_systemd's session bus, which Xfce's session uses and where at-spi-bus-launcher runs. Accessibility switched on (`toolkit-accessibility`, AT-SPI's `IsEnabled`) at install for toolkits that wait for it (Chromium, Qt, AccessKit); GTK apps show regardless. Apps started after see it.
- What `ui` prints: each visible window, all apps' (agent-desktop's `list-windows`, visible and not minimized), or one app's with `--app <name>`; a line `<app>: window "<title>" <x>,<y> <w>x<h>`, then its elements indented by depth: role, `"name"`, `= "value"` when it says more than the name or a toggle's state, `[states]`, frame. Frames in a shot's pixels: AX's are the display's points from its top left, as a macOS shot's pixels are (1600×900); AT-SPI's are the screen's pixels (1920×1080). Left out: elements with no frame or an empty one, hidden or offscreen ones, nameless leaves with no value. Two agent-desktop runs: `list-windows`, then one `batch` of the windows' snapshots.
- macOS's menu bar is out of the app's windows: `ui` puts the frontmost app's first (agent-desktop's `menubar` surface), `<app>: menubar 0,0 1600x30` and its menus, with an open menu's items (a closed one's have empty frames). A popup a control opens (a pop-up button's menu) is in its window's tree. Not the Dock: apps are opened with `exec open -a`.
- No `--json`: one element a line with every field trivm reads is what an agent and a script grep; agent-desktop's JSON carries refs that mean nothing outside it.
- `click <vm> --name <text> [--app <name>] [--right] [--double]`: the element whose name is the text, else the one whose name holds it, ignoring case; more than one, or none, is an error listing them; clicked at its frame's middle through the display as `click <x> <y>` does, a pointer click as a person makes, not an accessibility action.
- agent-desktop's JSON is read by a small parser of trivm's own: no serde for one format.
