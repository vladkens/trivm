# macOS and Linux on Virtualization.framework

trivm's first version: an agent creates a macOS 27 or Ubuntu 24.04 VM with one command and no clicks, starts it in the background, runs commands and copies files over SSH, and sees and drives its screen from the host; the person opens a window onto it. Done when an agent installs wavo-app v0.3.0 in both and takes a screenshot of it, unattended.

## Decisions

- Commands: `create <system> [--name <vm>] [--cpus n] [--memory GiB] [--disk GiB]`, `start <vm>`, `stop <vm> [--force]`, `list`, `delete <vm>`, `ip <vm>`, `exec <vm> -- <cmd>`, `ssh <vm>`, `cp <src> <dst>` (`<vm>:<path>` on either side), `shot <vm> [file]`, `click <vm> <x> <y> [--right] [--double]`, `type <vm> <text>`, `key <vm> <keys>` (`cmd+space`, `enter`), `open <vm>`. A VM's name defaults to its system's. The arguments parsed by hand.
- Systems, each pinned by URL and SHA-256 in the code:
  - `macos-27`: Apple's IPSW of 27.2 (26B123).
  - `ubuntu-24.04`: Canonical's arm64 cloud image of a dated release, with Xfce on X11 (LightDM, logged in automatically) installed by cloud-init on the first boot. The image is qcow2, which VZ doesn't read: a reader of our own writes it as a sparse raw disk (`miniz_oxide` for its deflated clusters; the `.tar.gz` beside it holds only the root filesystem, with nothing to boot).
- Files: `~/.trivm` (`TRIVM_HOME`): `cache/` for downloads, kept; an SSH key of trivm's own, `id_ed25519`; a folder per VM with `config` (`key = value` lines), `disk.img` (raw, sparse), the platform's files (macOS: `aux.img`, `hardware.bin`, `machine.bin`; Linux: `efi.bin`, `seed.iso`), and while it runs `pid`, `ctl.sock`, `log`.
- System tools only: `curl` (downloads, resumed), `shasum`, `ssh`, `scp`, `ssh-keygen`, `hdiutil makehybrid` (cloud-init's `cidata` ISO), `caffeinate`, `codesign`.
- A running VM is a process of its own: `start` runs `trivm _run <vm>` in a new session, its output to `log`, and waits for SSH. It owns the VZVirtualMachine on the main thread of an accessory NSApplication (no Dock icon), keeps the Mac from idle sleep while the VM runs (`caffeinate -i -w <pid>`) and answers one request per connection on `ctl.sock`: `stop`, `shot`, `click`, `type`, `key`, `open`. The VM ends with the process; `stop` asks the guest to shut down, then stops it after a timeout.
- The display from the host, as Vitrine does it (VitrineVZ `DisplaySink.swift`, Apache-2.0): a VZVirtualMachineView in an opaque 4×4 borderless window at desktop level + 1, the view sized to the display in points; `shot` reads the IOSurface its layers show; clicks and keys are NSEvents sent to the view, which VZ hands to the guest's keyboard and pointer. `open` shows a normal window with the VM; closing it hides it again.
- Coordinates are a shot's pixels: macOS's display is 2× (3200×1800 pixels at 220 ppi), its shot is scaled to 1600×900; Ubuntu's is 1× (1920×1080).
- macOS: `VZMacOSInstaller` from the IPSW, then the first boot with `VZMacGuestProvisioningOptions` (macOS 27+, not in `objc2-virtualization` yet, declared by hand): the user `user`, password `1234`, logged in automatically, Remote Login on. trivm's key goes in by the first SSH login, the password given by trivm itself as `SSH_ASKPASS`. Then sleep, the screen saver and the screen lock off.
- Ubuntu: the raw disk grown to its size (cloud-init grows the partition), EFI boot (`VZEFIBootLoader`), the seed with the user `user` (password `1234`, sudo without one, trivm's key), the desktop packages and autologin; done when cloud-init reports done after its reboot.
- The guest's address from `/var/db/dhcpd_leases` by the MAC address kept in `config` (VZ's NAT hands them out through bootpd).

## Tasks

- [ ] 1. The command line, `~/.trivm`, the config, `list`, `delete`; downloads checked by SHA-256; trivm signs itself ad hoc with the `com.apple.security.virtualization` entitlement, which VZ needs, the first time it runs a VM (a signed copy renamed over the binary), so `cargo install` and `cargo build` work as they are.
- [ ] 2. The VM process: `_run`, the macOS and Linux configurations, `ctl.sock`, `start`, `stop`, the sleep assertion; a dead process's files cleaned up by the next `start` or `list`.
- [ ] 3. `create macos-27`: the IPSW, the installer with its progress, the first boot with the provisioning, the key, the tuning. Checked on this Mac.
- [ ] 4. SSH: `ip`, `exec` (its exit code passed on), `ssh`, `cp`.
- [ ] 5. The display: `shot`, `click`, `type`, `key`, `open`. Checked on the macOS VM: Spotlight opened by `key`, Terminal typed into, a shot read.
- [ ] 6. `create ubuntu-24.04`: the image, the seed, the first boot to the Xfce desktop; the same checks as 3–5 on it.
- [ ] 7. The proof: wavo-app v0.3.0's DMG installed and opened on macOS, its `.deb` on Ubuntu, a shot of each read; `readme.md` and `--help`.
