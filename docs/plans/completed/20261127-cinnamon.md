# Cinnamon, Linux Mint's desktop

Mint's bugs are its desktop's, Cinnamon's, and Mint has no arm64 build: `trivm create ubuntu-24.04-cinnamon` installs Linux Mint 22.3's Cinnamon, built from Mint's own source packages for arm64 on Ubuntu 24.04, Mint 22's base, on X11 with LightDM and slick-greeter, logged in automatically, so an app's bugs on Mint, such as Wavo's (wavo-app #82, Cinnamon's text scaling; #83, its keyboard layout), are reproduced in a VM. Done when, on this Mac, a fresh VM is created with no clicks; `exec`, `shot`, `click` and `type` work in it; `ui` lists a window's elements and `click --name` clicks one; `gsettings set org.cinnamon.desktop.interface text-scaling-factor 1.5` makes the text visibly larger in a shot; and a second keyboard layout, `ru`, is added, switched to with the keyboard, and read back as Cinnamon reports it (shots read).

## Decisions

- Which Cinnamon: Ubuntu 24.04's own is 6.0.4 (January 2024, Mint 21.3's); Mint 22.3 ships 6.6.9 (`packages.linuxmint.com`, `zena`'s `backport`), whose keyboard handling is new: XKB layouts and IBus input methods alike as input sources, `org.cinnamon.desktop.input-sources` (`sources`, `current`), set by Muffin's keymap and switched with Super+Space, where 6.0 had libgnomekbd's `org.gnome.libgnomekbd.keyboard`. That is what #83 is about, so Ubuntu's 6.0 would reproduce the wrong desktop. Mint builds for amd64 and i386 only, so trivm builds Mint's own source packages for arm64 in the guest, on the base Mint builds them on.
- The API: a system of its own, `ubuntu-24.04-cinnamon`, not `create ubuntu-24.04 --desktop cinnamon`. A system in trivm is one recipe, its desktop part of it (`ubuntu-22.04` is KDE, `debian-13` GNOME, `fedora-45` Xfce), and a VM is that system: its name in the VM's config is all `start`, `ui` and `list` go by. A `--desktop` flag would be one value on one system, ask for the other pairs (`--desktop gnome` on Ubuntu, Xfce on Debian) that nothing here proves, and need a field in the config, a check of the pair and a default VM name of its own beside the person's `ubuntu-24.04`. The name says what it is, Ubuntu 24.04 with Cinnamon, and not Mint: Mint's own tools, repository and kernel aren't in it (the roadmap leaves Mint itself out).
- What is built: the 12 of Mint 22.3's source packages that are built for an architecture, from `zena`'s `backport`, in the order they need each other: cinnamon-desktop, cinnamon-menus, xapp, cjs, muffin, cinnamon-session, cinnamon-settings-daemon, cinnamon-control-center, cinnamon-screensaver, nemo, cinnamon, slick-greeter. Mint's packages are native: a tarball is the whole source with its `debian/`, pinned by its SHA-256 from Mint's `Sources`. Mint's own `+zena` packaging, made for this base, builds on Ubuntu 24.04 arm64 as it is: `apt-get build-dep` finds every build dependency in Ubuntu (cjs 115 on Ubuntu's mozjs 115), with the `nocheck nodoc` profiles.
- Taken as Mint built them, its 9 packages for any architecture: those Cinnamon needs that Ubuntu lacks (`xapp-symbolic-icons`, `iso-flag-png`) or has older (`python3-xapp` 3.0.3, Ubuntu's 2.4.1), its translations (`cinnamon-l10n`), and Mint's artwork: `mint-artwork` and the themes, icons and cursors it depends on, which set Mint's look as defaults (Mint-Y, the Ubuntu font, Mint's background, slick-greeter's). The rest comes from Ubuntu: Cinnamon's dependencies and recommendations (IBus, GNOME Terminal, NetworkManager among them), `fonts-ubuntu` for Mint's font, `xserver-xorg`, `x11-utils` for `click --name`, `dconf-cli`. Not Mint's apps (xed, Xreader, Warpinator) or tools.
- `packages.linuxmint.com` has no HTTPS (nothing answers on 443): HTTP, checked by the SHA-256, as Microsoft's CDN for Windows.
- The build runs in the guest at the first boot, in cloud-init's commands as root, from a folder of the seed holding the script, Mint's packages and the sources; each source's packages but `-dbg` are installed before the next builds. Then everything only the build needed goes: what the build made manual is marked automatic, Mint's packages manual again, the `-dev` and `-doc` packages purged, and `apt-get autoremove` takes the build's tools and dependencies, so the VM has Cinnamon's packages and their dependencies only. With 6 CPUs, the build took 11 minutes (muffin 3, nemo, cjs and cinnamon about 1.5 each); with `create`'s 4, the first `create` takes 21 minutes, a `create` from the packages kept 3.
- The packages built (30, 8 MB) are kept in the cache, in a folder named by a hash of the sources' SHA-256 (FNV-1a), so other sources build anew: the next `create` puts them in the seed and installs them with no build, and the same marking leaves the same packages. As Windows' media is made once.
- The seed's folder is read with `mount -o ro,norock`: Linux reads hdiutil's Rock Ridge before its Joliet, and that Rock Ridge has no names, so the sources came out as `cinnamon-desktop_662+zenata.xz`.
- `mint-cursor-themes` makes Mint's cursors the default with an alternative in `/usr/share/icons/default`, which a desktop's packages make and Ubuntu's cloud image lacks, so its install failed: the script makes the folder first.
- The login: LightDM, as Mint's, with `autologin-session=cinnamon` and slick-greeter, which its package makes LightDM's greeter; X started with `-s 0 -dpms`, never blanked by X; Cinnamon's screen saver, its lock and its power manager's blanking off in dconf's system database, as GNOME's are on Debian.
- The network: Cinnamon brings NetworkManager (its network applet), which apps ask whether they are online, as on Mint, so it gets the NIC. GNOME's way on Debian (`NM`: netplan's renderer for all, written after the packages) fails on Ubuntu 24.04's netplan 1.1.2, which gives NetworkManager no NIC matched by its driver, as `NETWORK_CONFIG`'s is for a clone's new MAC address: with it in place, NetworkManager's install ran netplan's generator, which failed, and the VM lost its network for good. So once Cinnamon is in, cloud-init's netplan goes for Ubuntu's desktop's: the renderer NetworkManager and no NIC of its own, so NetworkManager's own wired connection for every NIC, with DHCP's client id the MAC address, as networkd's (bootpd's lease keeps `1,<mac>`, the same IP). netplan leaves its udev rule keeping NetworkManager off the NIC in `/run`, so it is removed. networkd is disabled and stopped, and the address it got flushed before NetworkManager starts again: with networkd's address in place, NetworkManager only watched it (`connected (externally)`), and the first `apt-get install` in the VM restarted networkd (needrestart), which dropped the address with no config, and the VM was gone from the network. networkd's wait at boot goes with it, or each boot waits its 2 minutes. Tried on plain `ubuntu-24.04` VMs first: NetworkManager connected by `Wired connection 1`, connectivity full, the same IP, an `apt-get install` and a reboot later too, up in 2 seconds.
- Cinnamon now and then crashes within a second of its start: at 3 of about 20 first logins, a SIGSEGV in Mesa's llvmpipe copying a window's pixmap to a texture (`dri_set_tex_buffer2`, under Muffin's Cogl painting Cinnamon's actors; its core's backtrace), a race of the software renderer, not of trivm's setup. Its launcher then runs Metacity and asks "Cinnamon just crashed", with no panel. A LightDM restart logs in again and Cinnamon comes up, so `start` (and `create`) restarts LightDM while Metacity runs, and counts Cinnamon as up once it has run 3 seconds. The crash isn't fixed, only got past; a reboot or a later login can still meet it.
- `start` doesn't wait for Cinnamon's screen to light: Mint's background is dark, a third of it lit where `desktop` waits for half, so each start waited its full minute. Cinnamon draws its desktop as it starts, and its processes are waited for.
- GNOME Terminal is in the system's packages, Mint's terminal: Cinnamon recommends `gnome-terminal | x-terminal-emulator`, and apt took Zutty, which has no accessibility, so `ui` saw no window of it. `cups-client` too, for `lpstat`, which Cinnamon's printers applet runs: without it its script crashed at each login and left a report in `/var/crash` (with it, the applet says no printers, as Mint with none).
- `list` is as wide as the longest name and system: `ubuntu-24.04-cinnamon`, also the VM's default name, is 21 characters, past its 16.
- Which layout is on: Cinnamon 6.6 never writes `org.cinnamon.desktop.input-sources current` (its `keyboardManager.js` doesn't read or write it; it stays 0 after Super+Space); `org.Cinnamon.GetInputSources` on the session bus says it, its last field true for the source in use. That is the readme's example: an app that reads `current` on Mint always sees the first source.
- Licences: Cinnamon's sources are GPL-2+ and LGPL (their `debian/copyright`), Mint's artwork Mint's; all run as programs of their own in the guest, downloaded from Mint by the person's trivm at `create`, as a distro's image is; trivm hosts nothing.

## Result

On this Mac, in scratch VMs beside the person's, shots read:

- `create ubuntu-24.04-cinnamon` with no clicks: Cinnamon 6.6.9 logged in on X11 with Mint's
  theme, background and panel. Built from the sources in 21 minutes the first time (11 another
  time), the 30 packages kept (8 MB); a `create` from them in 1.5 to 3 minutes, the same packages
  either way, no build tools left. `stop` and `start` back to the desktop in 14 seconds; a `clone`
  got its own MAC address and IP from NetworkManager.
- NetworkManager has the NIC in the first boot: `connected` by `Wired connection 1`, connectivity
  full, the same IP after an `apt-get install` and a reboot. Before the fix, the VM lost its
  network at its first `apt-get install`.
- Cinnamon's crash: 8 VMs created in a row, the 8th's first login crashed, its core's backtrace in
  `dri_set_tex_buffer2`; a LightDM restart brought Cinnamon back. With Cinnamon killed into the
  fallback (Metacity, "Cinnamon just crashed"), `start` restarted LightDM and was back at the
  desktop in 38 seconds. A last `create` from the packages kept: up in 102 seconds, nothing in
  `/var/crash`, the printers applet's script says "No printers available!".
- `exec`, `shot`; `click` opened Mint's menu; `type` searched it and typed in a terminal; `key`.
- `ui` listed Nemo's and GNOME Terminal's elements; `click --name` clicked Nemo's "Go to parent
  folder", raised Nemo from under a terminal to click "Go to the previous visited location",
  refused a button under an always-on-top window (`is under window "Always on top"`), and opened
  GNOME Terminal's Help menu. Muffin reparents and stacks as Mutter does: `click --name`'s look at
  X's windows needed no change.
- `gsettings set org.cinnamon.desktop.interface text-scaling-factor 1.5`: Nemo's text, the title
  and the panel's clock half as large again (`Xft.dpi` 144).
- `sources [('xkb', 'us'), ('xkb', 'ru')]`, Super+Space: the panel's applet `us`, then `ru`; typed
  `ghbdtn` came out as `привет`; `org.Cinnamon.GetInputSources` marks `ru`, while
  `org.cinnamon.desktop.input-sources current` stays `uint32 0`.
