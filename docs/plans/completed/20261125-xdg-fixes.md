## Decisions

- Main merged in with no rebase: `join`, its code taken where both had changed it (7 files),
  then main's squash of it (0430f84) with `-s ours`, so the tree was main's and this plan; each
  fix main still needs was then made again on main's code, a commit each.
- The XDG move (729f0d6, d227d3d and its plan) dropped: main has the same layout.
- Kept, as main still has the bug:
  - Arguments with `=` quoted. Main leaves them bare, and macOS's zsh expands a word that starts
    with `=` to a program's path: `=ls` reached `printf` as `/bin/ls`, and `=nosuch` failed the
    whole command. A first word `x=1` set a variable instead of running as given. One argument
    is still a shell line, for a variable set on purpose.
  - `delete` checks the VM's data folder under its lock. Main stops the VM, then takes its lock;
    in between another `delete` may remove it and a `clone` or `create` make one of its name,
    which main then removes. The folder's inode, read before the stop, is compared under the
    lock, and a changed one ends with "was deleted meanwhile", as main's lock says of a `pid`
    removed while open.
- Dropped as main already has them:
  - A claim lost to a make in progress says so (eb22630): main's `claim`, the same check and
    words.
  - `put`'s temporary name made from its path (a2296de): main's `put`.
  - The cache's and the SSH key's locks beside their files (ab60871): main keeps them there.
  - `run`'s clone removed with its data folder last, for the reaper (5214b56's other half):
    main's `discard`.
  - The lock test waiting for locks let go (f5d4671): main's test waits with its own `soon`.
